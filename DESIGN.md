# Fulcrum Anvil — Design Specification

**Project:** `fulcrum-anvil` · **Binary:** `anvil` · **Status:** implemented — maintained as the behavioral specification

The behavioral specification `anvil` is held to: *what* the tool must do and
the *external contracts* it must honor. Requirements are numbered (**R#**) so
code and tests can cite them. When code and this document
disagree, one of them is wrong — fix whichever it is in the same change.

- **Fixed Contract** callouts mark things the implementation may **not** change
  because they are dictated by the operating system, the user-facing config, or
  cross-component agreement. Everything else describes what the code does.

## 1. Overview, goals, non-goals

Fulcrum Anvil hardens Debian/Ubuntu servers from a single declarative config file.
It connects over SSH, brings each enabled subsystem to a desired state
idempotently, and can preview, verify, score, and roll back its changes.

**Goals**

- R1. One static binary, one TOML config, no runtime dependencies on the target
  beyond a POSIX shell and standard distro tooling.
- R2. Declarative and idempotent: running twice makes no further changes; the tool
  reports precisely what changed.
- R3. Safe by construction: it must be impossible for a normal run to lock the
  operator out of SSH (see §7).
- R4. Auditable: every remote action is a shell script the operator can read
  (`--dry-run`), and every change is reversible (`rollback`).
- R5. Multi-host: apply the same config across a fleet, sequentially or in parallel.

**Non-goals**

- R6. Not a general configuration-management system (no arbitrary file templating
  DSL, no service orchestration beyond the built-in modules and plugins).
- R7. No agent installed on the target; no daemon; no phone-home.
- R8. Not cross-distro beyond Debian/Ubuntu family for v1 (design leaves room, but
  modules target `apt`/`systemd`/Debian paths).

## 2. Runtime & technology constraints

- R9. **Language:** Rust, 2021 edition, single `[[bin]]` producing `anvil`.
- R10. **Fixed Contract — SSH transport:** the tool MUST shell out to the system
  `ssh` binary (`std::process::Command`), never link a Rust SSH library. Rationale:
  inherit the operator's `~/.ssh/config`, agents, jump hosts, and known-hosts
  exactly. Remote scripts are delivered on stdin to a single `ssh` invocation.
- R10a. **Timeout watchdog.** `--timeout <SECONDS>` bounds every remote (and
  local) command: the child is SIGKILLed at the deadline via the owned process
  handle and reaped, the multiplexed control socket (R54) is closed with a
  bounded `ssh -O exit`, and the timeout surfaces as that module's failure. A
  stalled `apt-get`, a misconfigured `sudo`, or a dead NAT connection must not
  hang a run — critical under `--parallel`, where one stuck host holds a worker.
  Every exit path of the child-waiting code must reach its kill/reap; a dropped
  child handle neither kills nor reaps, and an escaped remote command outlives
  the tool as an orphan.
- R11. **Fixed Contract — remote shell:** every remote script runs under
  `bash` with `set -euo pipefail`. Scripts must be POSIX-bash compatible with
  bash ≥ 4 (targets run bash 5.x).
- R12. **No YAML, no Python, no embedded interpreters.** Config is TOML; remote
  logic is bash generated by the tool.
- R13. Crates: `clap` (derive), `serde` + `toml`, `serde_json`, `thiserror`,
  `anyhow` at the CLI boundary, `base64`. Ordering is a hand-written
  topological sort; host fan-out is a bounded `std::thread::scope` pool. No
  async runtime, no SSH crate.

## 3. Core abstractions

The names below are the ones the code uses (`src/engine.rs`, `src/modules/`);
[docs/08_architecture.md](docs/08_architecture.md) shows how they fit together.

- R14. A **Module** is a unit of hardening tied to one config section. Each module,
  given its config, can produce three things for a host:
  1. a **probe** (read-only check that reports whether the host already matches
     desired state), 2. an **apply** action (converges the host), and
  3. its **managed files** (the set of files it owns; see R16).
- R15. **Declarative managed-file model.** Modules never hand-write probe or
  apply bash. They declare a list of
  **ManagedFile { path, desired_content, mode, owner }** and
  **ManagedCommand { detect, converge, describe }** items. A shared engine renders
  the probe, apply, diff, and rollback bash from these declarations. This collapses
  an entire class of "check disagrees with apply" bugs into one well-tested engine
  and makes `diff`/`rollback` automatic instead of per-module.
- R15a. **File convergence semantics.** The probe compares content **and** mode
  (`stat -c '%a'`) **and** owner (`stat -c '%U:%G'`), so permission or ownership
  drift reports `DRIFTED` — for a hardening tool, a correct file at `0666` is
  drift. Apply enforces `chmod`/`chown` unconditionally (a no-op when already
  correct), so mode/owner drift is corrected even when content matches. Static
  content is materialized byte-exactly — compared with `cmp -s` against the
  decoded embedded blob and written via `base64 -d >`, never through `$(...)`
  (which strips trailing newlines) — so the declared bytes ARE the on-disk
  bytes; this is what makes `diff` exact (R89). A `ManagedFile` may carry a
  `path_resolver` (a bash snippet computing the path on the host, e.g. `getent`
  for a home directory), and an owner with a trailing colon (`user:`) checks
  the user only — chown login-group semantics, for pre-existing accounts whose
  group is not knowable at render time.
- R16. **Structured results.** The control plane works with typed values
  (`Verdict::{Aligned, Drifted(reasons)}`, `ApplyStatus`, `Change`). Remote
  scripts print line-leading markers (R87) and `engine.rs` parses them exactly
  once; nothing else in the tree reads script output.

## 4. CLI surface

**Fixed Contract — command and flag names.** These are the user interface and the
integration surface for scripts/CI; keep them stable.

- R17. Global: `anvil <SUBCOMMAND>`. Every subcommand that reads config accepts
  `-c, --config <PATH>` (default `harden.toml`). Machine output is opt-in via
  `--output json|ndjson`; `markdown` is accepted by `report` only and is
  rejected everywhere else with an error naming `report` (never silently
  falling back to JSON). Default is human terminal output.
- R18. Subcommands:

| Command | Purpose | Key flags |
|---|---|---|
| `apply` | Connect and converge the host(s) to desired state | `--dry-run/-n`, `--only <mods>`, `--verbose/-v`, `--output <fmt>`, `--parallel <N>`, `--no-check` |
| `validate` | Parse & validate config without connecting | `-c` |
| `check` | Detect drift on the host(s) | `-v`, `--output`, `--parallel` |
| `diff` | Preview exactly what `apply` would change (per-file unified diffs) | `--only <mod>`, `--output` |
| `rollback` | Restore modules to pre-hardening state from backups | `--only <mods>`, `--dry-run/-n`, `--output`, `--parallel` |
| `status` | Per-host module summary (enabled / drifted / compliant) | `--output`, `--parallel` |
| `score` | Run a Lynis audit, print the hardening index | `-t, --threshold <N>` (exit non-zero below), `--output`, `--parallel` |
| `report` | Compliance report of module coverage by CIS category | `--output json\|markdown`, `--check` (include live drift) |
| `doctor` | Preflight: config parses/validates, plan resolves, plugins trusted, every host reachable over the real transport (incl. `sudo -n` for non-root) | `--output`, `--timeout` |
| `init` | Generate a starter/reference config | `-o, --output <PATH>`, `--profile <NAME>`, `--full` |
| `plugins` | Manage plugins (subcommands, e.g. `list`) | — |
| `profiles` | Manage profiles (subcommands, e.g. `list`) | — |

- R19. `--only` takes a comma-separated list of module ids (see §8); an unknown
  or empty entry is a hard error listing the enabled modules — never a silent
  exit-0 no-op, which a hardening gate would read as "green". `--parallel N`:
  `1` = sequential (default), `0` = all hosts at once, `N` = up to N concurrently
  (`apply`/`check`/`status`/`rollback`/`score`; `diff`/`report`/`doctor` do not
  take it).
- R19a. Every fleet command also accepts `--host <a,b,…>` / `--exclude <a,b,…>`
  to target a subset of `[[hosts]]` by address (config order preserved; a
  `--host` entry matching no configured host is a hard error) and
  `--timeout <SECONDS>` (R10a).
- R20. `--dry-run` renders the exact scripts/changes and performs no remote
  mutation. `apply --no-check` skips the fast drift pre-pass and applies every
  enabled module (legacy/forced mode).

## 5. Configuration schema

Config is TOML. **Fixed Contract — every section name and field name below is a
public config key.** Types, defaults, and validation are specified per field.
Unknown keys are rejected (`deny_unknown_fields`) so typos fail loudly.

### 5.1 Top level

- R21. `[host]` (required) or `[[hosts]]` (repeatable, for a fleet). Plus one
  optional `[<module>]` table per module (presence = module enabled; absence =
  disabled). Plus optional `[execution_order]` and a top-level `profile`/`include`
  (see §11).

`HostSpec` (`[host]` / `[[hosts]]`):

| field | type | default | notes |
|---|---|---|---|
| `address` | string | — | hostname/IP (required) |
| `user` | string | — | SSH login user (required) |
| `port` | u16 | 22 | SSH port |
| `identity_file` | string? | none | SSH key path |
| `ssh_options` | [string] | `[]` | extra `-o` options passed to `ssh` |

- R22. **Validation:** `address`/`user` non-empty; `port` in 1–65535; if multiple
  hosts, each validated independently. Provide clear, field-named error messages.

### 5.2 Module sections (enable by presence)

Each section deserializes to a spec; every spec also accepts an `order_override`
(`order`/`before`/`after`) — see §6. Selected fields (full list per module):

- R23. `[sshd]` — `disable_root_login`(bool, true), `disable_password_auth`(bool,
  true), `disable_empty_passwords`(bool, true), `disable_x11_forwarding`(bool,
  true), `port`(u16, 22), `max_auth_tries`(u8, 3), `login_grace_time`(u16, 30),
  `client_alive_interval`(u16, 300), `client_alive_count_max`(u8, 2),
  `allow_users`([string]), `strong_ciphers`(bool).
- R24. `[firewall]` — `default_incoming`(string, "deny"), `default_outgoing`
  (string, "allow"), `restrict_ssh`(bool), `allow`/`deny`
  (array of `WallRule { port:string, proto:string?, from:string?, comment:string? }`).
- R25. `[fail2ban]` — `bantime`/`findtime`(string durations), `maxretry`(u8),
  `jails`(map name → `JailDef { enabled:bool?, port:string?, maxretry:u8?,
  bantime:string? }`).
- R26. `[updates]` — `security_only`(bool), `auto_reboot`(bool),
  `reboot_time`(string "HH:MM"), `remove_unused_deps`(bool).
- R27. `[users]` — `create`(array of `Account { name, sudo:bool, shell:string?,
  ssh_authorized_keys:[string]? }`). **Validation:** `name` restricted to a safe
  charset (used in sudoers paths).
- R28. `[kernel]` — `harden_network`(bool), `restrict_dmesg`(bool),
  `restrict_kernel_pointers`(bool), `extra_sysctl`(map string→string).
- R29. `[kernel_modules]` — `blacklist_filesystems`, `blacklist_squashfs`,
  `blacklist_vfat`, `blacklist_usb_storage`, `blacklist_network_protocols` (bools).
- R30. `[ssh_crypto]` — (no user fields beyond `order_override`; applies a strong,
  PQ-aware KEX/cipher/MAC policy).
- R31. `[suid]` — `extra_whitelist`([string] abs paths), `scan_paths`([string]),
  `exclude_paths`([string]).
- R32. `[dns]` — `dns_servers`([string]), `fallback_servers`([string]),
  `dnssec_strict`(bool), `dns_over_tls`(bool).
- R33. `[process]` — `disable_core_dumps`(bool), `disable_sysrq`(bool),
  `pass_max_days`/`pass_min_days`/`pass_warn_age`(u32), `hidepid`(bool).
- R34. `[pam]` — `minlen`(u32), `require_uppercase`/`_lowercase`/`_digit`/
  `_special`(bool), `enable_faillock`(bool), `deny`(u32), `unlock_time`(u32),
  `umask`(string), `tmout`(u32).
- R35. `[packages]` — `install`([string]), `remove`([string]).
- R36. `[crowdsec]` — `collections`([string]), `bouncer_mode`(string:
  iptables|nftables).
- R37. `[auditd]` — `rule_set`(string, e.g. "cis-level1"). The admissible names
  live in one constant (`schema::AUDITD_RULE_SETS`) shared by config validation
  and the module, so a set cannot be validated without a shipped rule body.
- R38. `[lynis]` — (audit only; no fields beyond `order_override`).
- R39. `[filesystem]` — `tmp_noexec`(bool), `check_sticky_bits`(bool),
  `check_world_writable`(bool), `aide_baseline`(bool).
- R40. `[docker]` — `iptables_off`(bool), `userns_remap`(bool), `rootless`(bool).
- R41. `[tls]` — `provider`(string: certbot|acme.sh), `domains`([string]),
  `email`(string?), `webroot`(string?).
- R42. `[hetzner]` — `server_name`(string), `firewall_name`(string), `rules`
  (array of `CloudEdgeRule { direction, protocol, port:string?, source_ips:[string],
  description:string? }`). Runs **locally** via `hcloud` CLI (see §8).
- R43. `[headscale]` — `version`, `server_url`, `listen_addr`, `db_path`,
  `acl_policy`(string?)/`acl_policy_path`(string?), `auth_keys`(array of
  `AuthKeySpec { name, reusable:bool, expiration:string }`), `headplane`(bool),
  `headplane_version`(string?), `headplane_listen`.
- R44. `[tailscale]` — `login_server`, `auth_key`, `hostname`(string?),
  `accept_routes`(bool), `tailnet_only_ssh`(bool).
- R45. `[greptimedb]` — `http_port`/`grpc_port`/`mysql_port`/`postgres_port`(u16),
  `data_dir`, `listen_address`, `version`. `data_dir` must be an absolute path
  without whitespace or `:` — it is embedded in the unit's docker `-v` flag,
  where neither can be quoted; validation rejects anything else up front.
  `version` defaults to a pinned release (`v0.9.5`) and must match
  `vMAJOR.MINOR.PATCH`; floating tags (`latest`) are rejected — a
  default-enabled section must not deploy an unreproducible image.
- R46. `[vector]` — `greptimedb_host`, `greptimedb_grpc_port`/`_http_port`(u16),
  `db_name`, `extra_log_files`([string]), `scrape_interval_secs`(u16).
- R47. `[execution_order]` — `modules`([string]): explicit total order override.

- R48. **Validation rules (general):** every string interpolated into remote bash
  must be validated or escaped (see R55). Numeric ranges enforced (ports, ages,
  thresholds). `reboot_time` matches `HH:MM`. Firewall policies ∈ {deny, allow,
  reject}. Enum-like strings validated against allowed sets with a helpful
  "expected one of …" message. All validation runs before any connection.

## 6. Execution model

- R49. **Pipeline:** parse TOML → resolve `include`s → apply `profile` defaults →
  expand `${VAR}` / `${VAR:-default}` from the environment in every string value
  (shell `:-` semantics — the default applies when the variable is unset *or*
  empty; a referenced variable that is unset with no default is a hard error, so
  a missing secret fails at load instead of becoming an empty string) →
  deserialize & validate → build per-host plan → connect → run.
  `profile`/`include` keys are consumed and removed before module
  deserialization; env expansion runs before plugin-section extraction so
  plugin-bound sections get it too.
- R50. **Two-phase apply (default):** first a fast **batch probe** runs every
  enabled module's read-only check concurrently on the host and reports
  drifted/aligned; then `apply` only converges drifted modules. `--no-check`
  forces all. `--dry-run` renders scripts without executing.
- R51. **Ordering:** modules run in a deterministic order computed from (a) each
  module's default order, (b) user `before`/`after` hints and `[execution_order]`,
  producing a topological sort with stable tie-breaking. The resolver must detect
  cycles and report the offending path, and must enforce the safety constraints in
  §7 as hard edges (rejecting configs that violate them).
- R52. **Idempotency:** each module detects current state and only acts on
  divergence, printing a change indicator only when it actually changed something.
- R53. **Multi-host:** apply/check/etc. run across all hosts; `--parallel` bounds
  concurrency. A failure on one host does not abort others; the run's exit code
  reflects the aggregate (see §13).
- R54. **SSH connection reuse.** `ssh` runs with `ControlMaster=auto` and
  `ControlPersist=60s` on a per-host control socket, so the probe pass, apply
  pass, and per-module calls to a host share one TCP/auth session.

## 7. Safety invariants (non-negotiable)

These are correctness requirements, enforced in code and covered by tests.

- R55. **Fixed Contract — shell-escape everything.** Every config-derived value
  interpolated into remote bash passes through a single quoting function
  (single-quote wrap with `'\''` escaping). Trusted compile-time literals are the
  only exception. This is the primary injection defense.
- R56. **Never lock out SSH — firewall.** The firewall module MUST add an allow
  rule for the effective SSH port **before** enabling the firewall, and the
  firewall MUST run **after** the sshd module (so the effective port is known).
  Enabling the firewall before permitting SSH is a spec violation.
- R57. **Never lock out SSH — sshd / crypto.** Any change to `sshd_config` or SSH
  crypto MUST be validated with `sshd -t` before reloading, and MUST auto-revert
  (restore the prior file, no reload) if validation fails. sshd and ssh_crypto run
  in separate ordered waves so a crypto change can't silently break a config change.
- R58. **Updates & reboot last.** The updates module (and any reboot) runs after
  all other modules, so a mid-run reboot can't strand the rest of the plan.
- R59. **PAM is never hand-edited.** The PAM module writes `pwquality.conf` /
  `faillock.conf` (and equivalents) and MUST NEVER write files under
  `/etc/pam.d/` itself. It activates `pam_pwquality`/`pam_faillock` only via
  `pam-auth-update` profiles, verifies the merged stack, and backs out
  on a wrong shape.
- R60. **Backup before overwrite.** Any module that overwrites an existing file
  first copies it to a backup (see §9) so `rollback` can restore it.
- R61. **Cloud firewall lockout guard.** The Hetzner (cloud) firewall MUST always
  include an inbound rule permitting the configured SSH port; it must be impossible
  to set a cloud firewall that drops management SSH.
- R62. **Tailnet-only SSH guard.** When restricting SSH to a tailnet, a working
  fallback path must remain until the tailnet is confirmed up.

## 8. Module catalog

Each module has: a config section (§5), a **Fixed Contract** for the host artifacts
it produces (the OS-level facts that make it *this* hardening step), drift
detection, and rollback via backups. The exact directive *values* and command
*flags* below are fixed (they are what hardening means); the *variable names* and
*script structure* are the implementer's choice.

- R63. **sshd** — Writes an sshd drop-in (e.g. `/etc/ssh/sshd_config.d/…`) with:
  `PermitRootLogin no`, `PasswordAuthentication no`, `PermitEmptyPasswords no`,
  `Port <port>`, `MaxAuthTries <n>`, `LoginGraceTime <n>`, `ClientAliveInterval
  <n>`, `ClientAliveCountMax <n>`, optional `AllowUsers <list>`, and (if
  `strong_ciphers`) strong `Ciphers`/`MACs`. Validate `sshd -t`, then reload;
  revert on failure (R57).
- R64. **firewall** — `ufw`: `ufw default <in> incoming`, `ufw default <out>
  outgoing`, allow SSH port (R56), then user allow/deny rules, then `ufw --force
  enable`. Drift = ufw inactive, SSH not allowed, or rule set differs.
- R65. **fail2ban** — install `fail2ban`; write a jail config
  (`/etc/fail2ban/jail.d/…`) with global `bantime`/`findtime`/`maxretry` and each
  configured jail; enable & reload the service.
- R66. **updates** — configure `unattended-upgrades` (security-only if set), enable
  periodic apt config, set auto-reboot & `reboot_time`, optionally
  `apt-get autoremove`. Runs last (R58).
- R67. **users** — for each account: `useradd -m -s <shell>` if absent; if `sudo`,
  a `/etc/sudoers.d/<name>` drop-in with `…NOPASSWD:ALL` at mode `0440`; sync
  `~/.ssh/authorized_keys` (dir `0700`, file `0600`, correct owner).
- R68. **kernel** — sysctl drop-in (e.g. `/etc/sysctl.d/…`) applying network
  hardening keys, `kernel.dmesg_restrict`, `kernel.kptr_restrict`, and any
  `extra_sysctl`; `sysctl --system` to load. Tolerate keys the running kernel
  rejects without failing the module.
- R69. **kernel_modules** — modprobe blacklist drop-in (`install <mod> /bin/false`
  lines) for the selected groups (rare filesystems, squashfs, vfat, usb-storage,
  uncommon network protocols); `update-initramfs -u`. Drift compares against loaded
  modules with underscore/dash normalization.
- R70. **ssh_crypto** — a separate sshd drop-in setting strong
  `KexAlgorithms`/`Ciphers`/`MACs`/`HostKeyAlgorithms`, filtering the KEX list to
  what the host's `ssh` supports (keeping post-quantum algorithms where available,
  falling back on older hosts). Validate + reload + revert (R57).
- R71. **suid** — scan `scan_paths` for setuid/setgid binaries, compare against a
  built-in stock allowlist plus `extra_whitelist`, and strip unexpected bits
  (`chmod u-s,g-s`); persist a state file so drift can be detected. Never touch
  whitelisted stock binaries.
- R72. **dns** — systemd-resolved drop-in
  (`/etc/systemd/resolved.conf.d/…`) with `DNS=`, `FallbackDNS=`, `DNSSEC=`,
  `DNSOverTLS=`; restart resolved; verify with `resolvectl status`.
- R73. **process** — disable core dumps (limits + `coredump.conf`), optional
  `kernel.sysrq=0`, `login.defs` password-aging (`PASS_MAX/MIN/WARN`), optional
  `/proc` `hidepid=2` remount + persistent mount unit. `login.defs` is a shared
  distro file edited in place: like pam's UMASK edit, the first change takes a
  `.anvil.bak` backup so `rollback` can restore it (R60/R88).
- R74. **pam** — write `pwquality.conf` (minlen, char-class requirements) and, if
  enabled, `faillock.conf` (`deny`, `unlock_time`); set login `UMASK` and shell
  `TMOUT`; activate pwquality and faillock via `pam-auth-update` (R59).
- R75. **packages** — `apt-get install` the `install` list and `apt-get purge` the
  `remove` list, each with a lock-timeout option; verify each package's dpkg state
  before reporting success. Config-derived package names are shell-escaped and
  verified in a loop.
- R76. **crowdsec** — install CrowdSec and the firewall bouncer for `bouncer_mode`
  (iptables/nftables); install `collections`; enable services. Behavior adapts if
  fail2ban is also enabled (avoid conflicting bans).
- R77. **auditd** — install `auditd`; load the CIS rule set named by `rule_set`
  into `/etc/audit/rules.d/…`; load rules. Debian/Ubuntu paths.
- R78. **lynis** — install `lynis`, run an audit, parse and report the hardening
  index; `score` uses this and can enforce `--threshold`.
- R79. **filesystem** — `/tmp` `noexec,nosuid,nodev` via a `tmp.mount` drop-in;
  optional sticky-bit and world-writable scans; optional AIDE install + baseline
  init. Two-phase drift so a fresh box reports correctly.
- R80. **docker** — write `/etc/docker/daemon.json` (merge, not clobber) with
  `iptables` off and/or `userns-remap`; optional rootless setup; restart docker
  when the config changed.
- R81. **tls** — issue/renew certificates via `certbot` or `acme.sh` for `domains`
  (webroot or standalone), wire a strong nginx TLS server block; validate `nginx
  -t` and revert on failure.
- R82. **hetzner** — **runs locally** using the `hcloud` CLI: create/update a cloud
  firewall (`firewall create` / `set-rules`) from `rules` and apply it to
  `server_name`. Always keeps the configured SSH port open (R61).
- R83. **headscale** — install headscale at `version`, write `config.yaml`
  (server_url, listen, db, optional ACL policy), a systemd unit, and pre-auth keys;
  optionally install Headplane (web UI) at its version/listen. Restart on config
  change.
- R84. **tailscale** — install tailscale, `tailscale up` with `--login-server`,
  `--auth-key`, `--accept-routes`, optional hostname; optional tailnet-only SSH
  with a fallback guard (R62).
- R85. **greptimedb** — run GreptimeDB (pinned image `version`) via Docker with a
  systemd unit; bind its ports to loopback; data dir with non-world-writable perms.
- R86. **vector** — install Vector, configure it to scrape journald + `extra_log_files`
  and ship to GreptimeDB (`greptimedb_host`, gRPC/HTTP ports, `db_name`,
  `scrape_interval_secs`); systemd-managed.

## 9. Host-artifact contracts

- R87. **Fixed Contract — change reporting.** Each remote step prints one
  line-leading marker: `CHANGED:`, `DRIFTED:`, `OK:`, or `FAILED:`. The
  vocabulary is defined once, in `engine.rs`, and parsed there into typed
  results (R16): any `DRIFTED:` line is drift, any `FAILED:` line fails the
  module, and `CHANGED:` without `FAILED:` is a change.
- R88. **Backups.** Before overwriting any managed file, copy it to
  `"<path>.anvil.bak"`. `rollback` restores from these. **Change manifest:**
  each apply also writes a per-run manifest of the files it created or modified
  under
  `/var/lib/anvil/runs/`, so rollback can *remove* files the tool *created* —
  a `.bak`-only scheme cannot undo a creation.
- R88a. **Rollback beyond ManagedFiles.** Two further channels: a module that
  edits a shared distro file inside a `ManagedCommand` (e.g. `/etc/login.defs`)
  declares it as a **command_file**, and rollback restores it from
  `.anvil.bak` with restore-safe semantics — restore when a backup exists,
  otherwise leave the file alone (never delete a shared system file the tool
  did not create; a second rollback is a safe no-op). For state the file model
  cannot express, a module may supply a **rollback script** that runs last and
  emits its own markers (suid replays the modes recorded in its state file,
  then consumes the state file so a repeat is a no-op).
- R89. **Diff preview.** `diff` shows a unified diff per managed file: it reads
  the current remote file (base64-framed) and diffs it against the declared
  `desired_content` (R15) — never by scraping generated bash. Host-computed
  content is reported as `computed`.
- R90. **Fixed Contract — managed-file identity.** File *paths* and *content* the
  tool writes (sshd directives, sysctl keys, jail configs, drop-in locations) are
  the hardening contract and are specified per module in §8. Drop-in *filenames*
  may carry the tool's brand — implementer's choice, but keep them stable once
  chosen so drift/rollback are consistent, and pick the numeric prefix by the
  directory's precedence rule: first-match-wins directories (`sshd_config.d`)
  need a LOW prefix (`05-anvil*.conf`) so the drop-in beats distro files like
  `50-cloud-init.conf`; last-definition-wins directories (`sysctl.d`,
  `modprobe.d`, `resolved.conf.d`, `jail.d`, audit `rules.d`, `apt.conf.d`)
  need a HIGH prefix (`99-anvil*`). A wrong-direction prefix silently loses to
  the distro.

## 10. Plugins

- R91. Users can extend the tool with out-of-tree plugins discovered from a known
  directory (e.g. `~/.config/anvil/plugins/<name>/`).
- R92. A plugin provides a manifest (`plugin.toml`: name, order/`before`/`after`,
  and the config section it binds to) plus `apply.sh` and optional `check.sh`.
  Plugins are addressed as `plugin::<name>` in ordering and results.
- R93. **Security:** plugin names are validated against `^[A-Za-z0-9_-]+$` (no path
  separators); plugin directories/files must be owned by the invoking user (reject
  world/other-writable or foreign-owned plugins); `{{VAR}}` substitutions from
  config are shell-escaped, and an undefined variable is an error, not an empty
  string. A malformed plugin is skipped with a warning, never aborting discovery.

---

## 11. Profiles & config includes

- R94. **Profiles.** `profile = "<name>"` at the top of a config applies a built-in
  preset's defaults, which the user's own keys then override. **Fixed Contract —
  built-in profile names:** `minimal`, `cis-level1`, `web-server`, `ci-runner`.
  Custom profiles may be discovered from a user directory. `init --profile <name>`
  scaffolds from one.
- R95. **Includes.** `include = ["base.toml", …]` merges other TOML files before
  the local file, left-to-right, with arrays concatenating and tables deep-merging;
  relative paths resolve against the including file; include cycles are detected and
  reported. `profile`/`include` keys are stripped before module deserialization.
  Included files are held to the same trust model as plugins (R93): a symlinked,
  group/world-writable, or foreign-owned include is rejected before it can
  inject module config; absolute or `..`-traversing include paths warn on
  stderr.

## 12. Output & reporting

- R96. **Human output** (default): concise per-module lines with color, a per-host
  summary (counts of changed/ok/failed/drifted), and a spinner/progress indicator
  for long fan-outs.
- R97. **Machine output** (`--output json`): a stable JSON document per host with
  module results; `check`/`status`/`score`/`report` each define their schema.
  `--output ndjson` (where offered) streams one JSON object per line for piping.
  `report --output markdown` emits a CIS-category coverage table.
- R98. **Fixed Contract — result status vocabulary** in machine output:
  `changed` / `ok` / `failed` / `dry-run` (and `skipped`) for apply-family rows.
  `check`/`status` module rows always carry `status`
  (`aligned`/`drifted`/`failed`) — the key is present on every row, success or
  failure, so consumers get one stable accessor — with drift detail in an
  optional `reasons` array and failure detail in `error`. Keep these strings
  stable for consumers.
- R98a. **Stream contract:** stdout carries only the requested output (human
  table or machine document); every diagnostic — errors, skipped-plugin
  warnings — goes to stderr, so `--output json` stays pipeable. Exit-code
  semantics differ by intent: `check` treats drift as actionable (non-zero),
  `status` as informational (zero unless a probe *fails*).

---

## 13. Error handling & exit codes

- R99. Use a typed error enum for library errors (config read/parse, SSH failure,
  module failure, ordering cycle, safety violation, unknown module, empty order),
  each with an actionable message; `anyhow` at the CLI boundary.
- R100. **Exit codes:** `0` success (no failures); non-zero when any host/module
  fails, when `validate` finds an invalid config, or when `score --threshold` is
  not met. A single host's failure must not abort the fleet; the aggregate
  determines the code. Safety-constraint violations and config errors fail fast
  before any connection.

## 14. Testing strategy

- R101. **Unit tests** per module asserting the *behavioral contract* of generated
  scripts (contains the required commands/paths/markers, backs up before writing,
  probe agrees with apply). Aim for parity between each module's check and apply.
- R102. **Fixed Contract — generated-bash syntax gate.** A single test builds a
  config (from the binary's own `init --full` template) that enables **every**
  registered module, generates every remote script, and runs `bash -n`
  (parse-only) on each — catching quoting/heredoc mistakes that unit tests miss.
  A companion test pins that every id in the module registry is planned and
  gated, so a new module cannot silently escape. Must run in CI (bash ≥ 4; an
  older local bash is stricter, so CI's target-matching bash is authoritative).
- R103. **Property/safety tests:** the ordering resolver never violates §7
  constraints and never emits a cycle silently; shell-escaping round-trips
  adversarial inputs (quotes, `$`, backticks, spaces); the firewall always allows
  SSH before enabling.
- R104. **Integration tests:** CLI parsing/exit codes without a host, plus a
  hermetic fake-`ssh` transport: the engine resolves `ssh` from `PATH`, so tests
  put a shim script first on the spawned process's `PATH` and drive
  `check`/`status`/`apply`/`diff`/`score`/`rollback`/`report` end-to-end — probe
  → converge sequencing, failure containment, exit codes, and JSON shape — with
  no DNS or network. `scripts/acceptance.sh <user@host>` is the opt-in
  end-to-end suite against an existing disposable box: apply → idempotency →
  CIS → reboot → PAM → drift → port move → rollback → re-apply
  (`docs/design/acceptance.md`).
- R104a. **Mutation testing** (`cargo mutants`, config in `.cargo/mutants.toml`):
  CI mutation-tests each PR's diff; full runs are periodic/manual. The
  deliberately-thin ssh/local/main layers are excluded. Treat a surviving mutant
  in safety-relevant code as a missing test, not noise.
- R105. **Diff-contract regression test:** an explicit test that, for
  every module that manages a file, `diff` produces a correct preview — closing the
  gap where a renamed internal variable could silently disable diff without any
  unit test failing.

## 15. Non-functional requirements

- R106. **Security posture:** no secrets logged; auth keys/tokens redacted in
  output; remote scripts contain no plaintext secrets beyond what the operator put
  in config; least-privilege command choices. Vendor software (CrowdSec, Docker
  Engine, Vector) installs from keyring-pinned apt repositories — a fetched,
  dearmored vendor key referenced via `signed-by=` — never by piping a
  downloaded script to a shell; apt then verifies the signature on every
  install, not just the first.
- R107. **Portability:** Debian 11/12, Ubuntu 20.04/22.04/24.04. Detect distro/init
  where behavior differs; degrade gracefully (skip with a clear message) rather than
  fail when a subsystem is absent.
- R108. **Performance:** fleet operations bounded by `--parallel`; SSH multiplexing
  (R54); the batch probe runs a host's module checks concurrently in one session.
- R109. **Robustness on fresh boots:** apt operations tolerate the dpkg lock held by
  cloud-init/unattended-upgrades (pass a lock-wait timeout) rather than failing.

## 16. Build, packaging & CI

- R110. `cargo` workspace with one binary crate `fulcrum-anvil` → `anvil`.
  Release profile stripped + LTO. Pin dependencies via `Cargo.lock`.
- R111. Packaging: a `vX.Y.Z` tag triggers `.github/workflows/release.yml`,
  which attaches static musl binaries (Linux x86_64, aarch64) and macOS
  binaries to a GitHub Release, with the matching `CHANGELOG.md` section as
  the notes. No Docker image, Nix flake or Homebrew formula yet.
- R112. CI: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo nextest run` (incl. the `bash -n` gate) plus `cargo test --doc`, and
  `cargo mutants --in-diff` on pull requests; release builds on tag. No network
  in any test — remote transport is exercised via the fake-`ssh` shim (R104).

## 17. Design choices

**Choices that shape the code:**

- I1. Declarative **managed-file/command** engine (R15) so probe/apply/diff/rollback
  derive from one declaration — eliminates the check-vs-apply drift bug class.
- I2. **Typed results** in the control plane; markers parsed once (R16, R87).
- I3. **Change manifest** for exact rollback, including undoing file *creations*
  (R88) — a backup-only scheme can't.
- I4. **Direct file diff** from declared desired content (R89).
- I5. **SSH connection multiplexing** (R54) for fleet performance.
- I6. **Explicit diff-contract regression test** (R105).

**Decisions the implementation took:**

- Q1. The line-marker protocol (§9) is kept for remote output; the control plane
  parses it once, in `engine.rs`, into typed results. No JSON envelope.
- Q2. The `harden.toml` section and field names are the public contract and
  were kept as-is.
- Q3. Host fan-out uses `std::thread::scope` with a bounded worker pool — no
  async runtime, no extra dependency.
- Q4. Debian/Ubuntu only. Modules assume `apt`, `systemd` and Debian paths; no
  RHEL seams were added.
